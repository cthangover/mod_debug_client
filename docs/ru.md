# Клиент отладки

Мод подключает локальный MCP-клиент к запущенному Cthangover. Доступные команды определяет активная коллекция после загрузки модов.

## Включить подключение

Добавьте `debug_client` в активную коллекцию и примените набор модов. Для разового запуска передайте `--with-mods=debug_client` после разделителя Godot `--`. Игра и ретранслятор должны работать под одной учётной записью в одной ОС. На Linux им нужен одинаковый `TMPDIR`, обычно `/tmp`.

Конфигурация MCP на Linux

```json
{
  "mcpServers": {
    "cthangover": {
      "command": "python3",
      "args": ["-B", "/absolute/path/to/DebugClient/mcp_stdio.py"]
    }
  }
}
```

На Windows укажите `py` в `command` и `["-3", "-B", "C:/path/to/DebugClient/mcp_stdio.py"]` в `args`. Ретранслятор обычно находит запущенную игру сам. Если запущено несколько экземпляров, добавьте в список `"--pid", "12345"` с PID нужного процесса. `--connect-timeout` задаёт ожидание игры в секундах, по умолчанию 5.

## Посмотреть состояние игры

```text
diagnose({"mod":"ognishchanin_game"})
inspect({"area":"node","path":"/root/SceneManager"})
describe({"query":"settings"})
run({"command":"settings.read"})
```

`diagnose` показывает диагностику компиляции и работы мода. `inspect` читает узел, кэш, сведения о процессе, ресурс или мод. `describe` ищет команды в живом каталоге. `run` выполняет зарегистрированную команду. Для команды мода укажите `provider`, параметры передайте в объекте `arguments`.

Запросу, меняющему состояние, назначайте свой UUID в `operation_id`. После обрыва проверьте судьбу запроса через `run({"command":"operation.status","operation_id":"<uuid>"})` перед повтором. Игра хранит ограниченную историю недавних операций.

Один процесс игры обслуживает один сеанс MCP одновременно. После отключения и включения мода запустите новый сеанс клиента. Собственная диагностика ретранслятора выводится в stderr.
